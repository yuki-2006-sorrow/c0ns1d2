# c0ns1d2 · 惊天魔盗团记忆库

个人记忆网站，基于 Astro 静态站点生成器。

## 项目结构

```
c0ns1d2/
├── src/
│   ├── pages/              # 页面路由
│   │   ├── index.astro     # 首页（星球可视化）
│   │   ├── events/         # 事件列表 + 详情
│   │   ├── people/         # 人物列表 + 详情
│   │   └── journal/        # 随笔列表 + 详情
│   ├── components/         # 组件（星球可视化等）
│   ├── content/            # 内容（Markdown）
│   │   ├── events/         # 22个事件
│   │   ├── people/         # 5个人物
│   │   └── journal/        # 随笔（待添加）
│   └── layouts/            # 布局模板
├── public/                 # 静态资源（图片、视频）
├── astro.config.mjs
└── package.json
```

## 本地开发

```bash
npm install
npm run dev      # 启动开发服务器 http://localhost:4321
npm run build    # 构建到 dist/
npm run preview  # 预览构建结果
```

## 添加新内容

### 书、电影、游戏与手动联想

编辑时可用 Ctrl/Cmd+S 保存当前表单，Esc 清空侧栏搜索。上传照片和编辑文件夹不会重置正在写的事件或联想；单张照片上限 10MB，上传后需要保存事件。若文件在其他窗口被修改，后台会提示而非覆盖。

时间索引支持总览、最近一件、加减缩放和键盘方向键；进入子文件夹可逐级返回，回到页面会恢复视野。开场可直接进入或重看，照片查看支持前后切换与 Esc 关闭。

时间索引的浅色绳把事件卡片牵到准确日期，暗红绳按当前视图内的发生顺序连接事件，可用「事件串绳」开关收起。卡片悬停或键盘选中时会突出对应绳子；同日及密集事件分层排放，手机可上下拖动查看。暗红绳表示时间顺序，手动联想仍独立录入。

继续使用原有 `启动.bat` 和 `/admin` 后台：

1. 左侧切到「书·影·游戏」，点「新建作品」，填写标题与类型。作者、封面、简介和正文都可留空；新条目默认草稿。
2. 保存后，切到编辑区的「联想」页签，点「记下一段联想」。先自由书写，标题和关联对象都可以暂时不填，正文支持 Markdown 长文。
3. 「关联与摘录」默认收起，需要时再选择另一条记忆或作品、补充摘录及页码。可以只留下连接，也可以多次记录同一件事引起的不同想法。
4. 联想本身及起点公开后可显示；如果填写了关联对象，对方也需要公开。前台短文直接读，长文显示开头并可进入 `/thoughts/[slug]` 完整阅读。
5. 本地站点的事件/作品页有「记下想到的」按钮，可以浏览时打开写作侧栏，先存成草稿，再从「在后台继续写」进入对应表单；收起侧栏保留文字，离开未保存页面会提示。线上静态站不显示这个本地编辑入口。
6. 回到「继续写」取消「公开这段联想」可收回；作品可单独取消公开。保存会等待预览构建完成，失败时显示错误。正文与联想页签切换不重画表单。

作品保存在 `src/content/works/`，联想单独保存在 `src/content/associations/`；后台生成的元数据为每行 JSON 值的 Markdown frontmatter。现有事件文件、文件夹和开场视频继续沿用。当前不预填作品或虚构联系，作品架为空时正常显示空状态。

`npm run test:associations` 检查持久化和公开边界；`npm run check:editor` 在临时副本与独立 Chrome 中验证录入、双向编辑和移动端，验证数据不会写进正式内容。Chrome 路径可用 `CHROME_PATH` 指定。

`npm run test:intro` 检查开场播放状态与本地视频分段读取；`npm run test:timeline` 检查卡片避让、挂绳端点及窄屏绕行。启动本地后台后，`npm run check:intro` 用真实开场视频验证点击、定格、跳过、重看和自然进入照片墙，默认地址为 `http://127.0.0.1:4323`，可用 `INTRO_ORIGIN` 指定其他端口。

### 公开范围与精选事件

- 事件 `draft: true` 为草稿；省略 `draft` 也默认不公开。审核后明确设置 `draft: false`。
- `major: true` 表示精选大事件，只有同时公开才会上首页照片墙；普通公开事件仍可从事件列表、时间线及人物页进入。
- 本地后台分别提供「公开发布」和「上照片墙」两个选项；新建事件默认草稿。
- 草稿浏览只在 `npm run dev` 且 `.env` 设置 `SHOW_DRAFTS=true` 时可用，正式构建不包含草稿浏览内容。本地后台仍能编辑全部记录。
- `npm run build` 自动检查公开事件路由数量、草稿标识是否残留及草稿浏览页；也可用 `npm run check:public` 单独检查现有 `dist`。
- `public/` 下的媒体会直接发布，不应用来存放尚未允许公开的附件。

### 添加事件
在 `src/content/events/` 新建 `.md` 文件：

```markdown
---
title: 事件标题
draft: true
major: false
date: 2026-10-19
persons: [朱浩宇, 曾浩鑫]
tags: [聚餐, 高三]     # 自定义分类标签，一个事件可以有多个
category: other        # core / food / exam / other（决定星球颜色）
color: "#9b59b6"
size: 30
images:
  - /images/xxx.jpg
videos:
  - /videos/xxx.mp4
---

事件正文内容...
```

**关于分类标签（tags）：**
- 你自己决定怎么分类，网站会自动生成每个标签的页面
- 一个事件可以属于多个标签
- 导航栏的「分类」页面会展示所有标签和每个标签下的事件数
- 事件详情页里的标签可以点击，跳转到该分类

### 添加随笔
在 `src/content/journal/` 新建 `.md` 文件：

```markdown
---
title: 随笔标题
date: 2026-10-19
author: 朱浩宇
tags: [日常, 感想]
---

正文内容...
```

### 添加图片/视频
把文件放到 `public/images/` 或 `public/videos/`，然后在 Markdown 里用 `/images/xxx.jpg` 引用。
