# 公网试用

当前采用用户电脑保存资料、Cloudflare临时通道提供HTTPS入口。用户明确选择先用临时地址，不购买域名或云存储。

## 使用

1. 运行「启动协作.bat」，确认本机可访问并已建立自己的站主账号。
2. 保存正在编辑的文字，再运行「启动公网试用.bat」。首次生成临时地址时会重启协作服务，需重新登录。
3. 地址显示后，可从其他电脑或手机打开。朋友在「登录／答题加入」中建立自己的账号；未登录访客只看站主明确开放的内容。
4. 「关闭公网试用.bat」只关闭公网通道，不删除资料，也不关闭本机记忆库。

电脑必须开机、联网，协作服务和通道都要运行。重复启动会复用当前通道；关闭后重新建立通道、重启电脑等操作会改变临时地址。临时通道适合测试，不保证长期可用。

## 原主站

`deployment/remote-origin.json`记录当前临时地址（它是访问地址，不包含账号或密码）。构建时从`deployment/pages-worker.mjs`生成`dist/_worker.js`。Cloudflare Pages直接提供构建白名单内的固定脚本、样式和原开场素材，避免视频经过站主电脑上传；页面、登录、访客内容及记忆照片/视频仍转发到协作服务检查权限。固定资源路由使用[Pages官方ASSETS绑定](https://developers.cloudflare.com/pages/functions/advanced-mode/)，不会回退到旧的静态事件页。

建议从原主站访问以使用上述固定资源加速；直接打开临时地址时，资源仍由电脑传输。已看过开场的浏览器不再自动下载整段视频，点击重看才加载。首页照片进入卡片区后按附近卡片加载，避免与开场争抢带宽。首次播放仍取决于访问者网络速度。

连接失败时，登录页可点击「重新连接」。读取等待过久会给出提示；保存、发布和上传不会自动重复发送。网络中断后先保留当前编辑页及文字。公网启动器现在会启动尚未运行的本机后台，并验证真实公网响应；通过后才更新主站配置，不会因为通道进程存在就误报连通。

首页提供记忆、时间线、书影游戏和想法入口；从首页登录或答题加入后返回首页。登录者的账号菜单可进入内容与草稿、新建记忆/作品/想法、改密码与访客视角；站主另有成员、准入及访客开放管理。旧`/admin`地址转到需要登录的协作后台，不开放无认证的本机个人后台。

电脑或通道离线时，首页仍可观看原开场并显示重新连接入口，登录页也保留重连界面。它们从构建的空内容壳生成，不含账号或记忆资料；内容详情和API仍返回503，不会退回旧的静态内容。预览部署域名不开放档案，使用正式的`c0ns1d2.pages.dev`入口。已经存在的历史静态部署和第三方保存的副本不会被这次转发自动删除。

生成新的临时地址时，启动器会更新`deployment/remote-origin.json`。更新该配置并提交推送、等待Pages部署成功后，主站才会接上新通道。临时地址本身在通道连通后即可访问。保留固定域名的长期方案需以后配置正式通道。

## 安全与本机工具

只连接有登录和权限检查的4324服务，不开放原来无登录的4323后台。远程禁止首次站主初始化，登录使用Secure、HttpOnly会话；POST校验来源与请求头，主站转发也先校验原浏览器来源。账号、问题校验资料、正文和附件仍保存在被Git忽略的`.local-collaboration`中。

通道工具位于被Git忽略的`data-tools/bin/cloudflared.exe`。本次由Cloudflare官方GitHub发布下载并核对SHA256。换电脑时从[Cloudflare官方下载说明](https://developers.cloudflare.com/tunnel/downloads/)获取Windows版本，放到同一位置。不要把本机资料库放进公开仓库。

开发检查：`node --test scripts/remote-entry.test.mjs`、`npm run test:collaboration`、`npm run build`。远程上传还受Cloudflare通道/代理的请求限制，本机500MB单文件上限不等于公网也能上传相同大小；大视频先准备较小播放副本。
