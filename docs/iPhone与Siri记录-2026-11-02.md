# iPhone 与 Siri 快速记录

目的：在 iPhone 上通过 Siri 唤起快捷指令，听写一个想法，写入私有个人空间。第一版保留原文，不要求现场分类，也不自动交给外部 AI。

## 手机配置

用 Safari 打开正式站 `/personal/me#iphone`，使用站主账号登录。在“iPhone · Siri 快速记录”中生成凭证。隔离预览生成的凭证仅对预览有效，不能用于正式站。

新建快捷指令，名称设为“记下想法”：

1. **听写文本**：中文，停顿后结束。空文本时停止。
2. **当前日期 → 格式化日期**：自定格式 `yyyyMMddHHmmssSSS`，在本次执行中固定，作为请求标识。
3. **追加到备忘录**：事先选择一条本机备忘录，追加“请求标识 + 听写文本”，先保存副本。网络失败时仍能找到原话。
4. **获取 URL 内容**：地址复制自配置页，方法 `POST`。
5. 请求头 `Authorization`：复制配置页提供的整段 `Bearer ...`。不要把凭证写在 URL 中。
6. 请求体选择 JSON，添加两个文本字段：`body` 使用听写文本的变量，`requestId` 使用格式化日期的变量。用字典字段构建请求，不手工拼接带引号的字符串。
7. 从响应取 `ok`，为 true 时朗读 `message`，否则显示 `error`。请求失败或超时不是保存成功。

第一次在手机解锁状态下手动运行，确认听写、备忘录和网站连接权限。然后说“嘿 Siri，记下想法”。锁屏、语言和权限表现需要在本人手机实测，本轮没有远程安装或实机运行快捷指令。

同一请求重试时，沿用原 `requestId` 和原文字会返回原收据，不追加第二条；更换标识表示新想法。第一版没有自动扫描备忘录和离线补传功能，失败后需按原标识重试或手动整理本机副本。

## 接口

`POST /api/personal/capture`，只接受 JSON 与手机专用 Bearer 凭证，不接受登录 Cookie 代替。正文最多 8000 字符，示例：

```json
{"body":"今天想到一个项目方向。","requestId":"20261102123045123"}
```

成功返回 `ok`、记录 ID、日期、接收时间、重复标记和反馈文字，不返回日记或其他个人资料。记录归入“随手想法”，标记为 Siri 来源，日期按北京时间计算。接口仅追加记录，不修改个人介绍、项目或已有记录。

如果没有写入成功，接口分别提示 `body` 字段缺失、不是文本、为空或超过8000字，不回显原文和凭证。修改快捷指令后需再次点右下角运行，动作下面保留的上一次输出不会随配置编辑而自动更新。

配置与停用：`/api/personal/devices` 仅供已登录站主管理，每个账号最多5个凭证，有效期一年。原始凭证只在创建时返回，服务器仅保存 SHA-256；凭证元数据和个人文字导出均不包含凭证明文或摘要。账号被停用、失去站主身份或凭证过期后不能写入。完整私有资料库备份包含凭证摘要，依旧需按私人文件保管。

网关只为上述路径开放原生客户端写入方式，其余写接口继续检查浏览器同源与登录。配置、阅读和导出接口不接受手机凭证作为登录凭据。

## 运行边界

- 当前资料仍由本人电脑提供；电脑休眠、断网或通道停止时，手机无法同步，先保留本机副本。
- 网页开发完成不能代表 iPhone 实机配置完成。本轮没有生成经过 Apple 签名的一键安装文件或 iCloud 分享链接，需本人在手机创建快捷指令。
- 新数据仍保存到统一资料库 `personal` 字段；设备凭证摘要单独位于 `personalDevices`，不进入 Git。
- 收到手机记录后刷新“记录”页即可查看。手机新增会更新版本号，避免旧浏览器页面覆盖新记录。
