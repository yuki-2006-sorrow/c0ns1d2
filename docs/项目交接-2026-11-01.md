## 1. 现在要做的产品

网站已从“事件记忆库”转向“利用私人素材共同创作作品的网站”。核心流程：

> 创作者浏览素材产生灵感 → 围绕话题选择片段 → 在剪辑台编排成图文混排作品（可嵌入音视频）→ 邀请共同创作 → 发布成品供访客阅读。

用户明确的取舍：

- 入口太多是混乱的根源，不能继续把回忆、事件、想法、作品各自做成平级主入口。
- 所有原始小事件、聊天记录、随笔、观点、照片、音视频都是素材。聊天导入只是一种素材类型。
- 网站核心是素材构成的作品，不能把全部旧事件直接包装成公开成品。
- 访客可看已发布作品；只有具有创作者资格的账号可进素材库。
- 创作者资格之外，继续尊重原素材的私人或分享范围，不自动将私人原文开放给所有创作者。
- “剪辑”当前指选择、截取文字、排序、串联、编排；成品形式已确认是图文混排，可嵌入音视频。
- 最新美术要求是极简、统一；不能继续出现展厅浅色、工作台深色、账号页另一套风格的割裂。

“专题”是前一阶段合并入口的成果，下一步应作为作品的话题组织方式，不能重新成为公开原始事件目录。

## 3. 已完成功能

### 3.1 作品与素材

- 独立作品存储，与原始素材分离；引用和编辑片段不修改原文。
- 私有素材库支持搜索、类型筛选、选择、展开原文与音视频预览。
- 可从单条素材开始创作，也可多选素材进入剪辑台；灵感选文经会话存储传递，不把私有正文放入 URL。
- 素材类型支持聊天、经历、图片、视频、音频、随笔、想法、观点；旧自动导入聊天映射为聊天类型。
- 剪辑台支持选取文字、修改引用、添加串联文字、重排及移除片段、说明、撤销与重做。
- 支持从服务器保存和恢复作品草稿，导出当前作品 JSON 备份。
- 首页作品展厅、作品阅读页、素材库、草稿列表和剪辑台已经串联。

### 3.2 协作、归属与发布

- 发起人可邀请具有创作者资格的账号参与作品。
- 保存使用 revision 校验，旧页面不能无提示覆盖别人的新保存。
- 修改记录记录真实账号与变化字段，作品保留版本、讨论和创作者署名。
- 发起人或站主可发布、更新发布、撤回。
- 发布创建独立快照；继续修改草稿不会改变访客正在阅读的已发布版本。
- 公开响应只包含作品采用的片段，不暴露素材 ID、完整原文、内部路径、历史与讨论。
- 作品媒体使用单独地址；撤回作品后，对应公开媒体失效。
- 旧事件、人物等原始资料路由及原始媒体 API 已在服务端限制创作者访问；旧访客分享入口停止作为公开发布方式。

当前共同创作是“保存 + 重新载入 + 冲突检查”，不是实时多人编辑；不能展示虚假的实时在线光标。

### 3.3 照片导入与改动可见性

- 补充上传预览、逐文件反馈、重试，以及修改者和变化字段的显示。
- 对受支持的既有远程图片增加授权读取与本地缓存，包含大小、类型等校验。
- 真实资料中发现的 8 个豆包 CDN 图片地址均返回 403。现有修复不能恢复这些已不可读取的原图，需要取得原文件或有效来源后重新导入。
- 不要将“增加容错和缓存”写成“所有旧照片已修复”。

### 3.4 减少入口与统一美术

- 旧回忆、作品、想法浏览曾统一到专题入口，原整理能力保留为创作者工具。
- 新的主结构为公开作品展厅，以及创作者使用的素材库、剪辑台、草稿。
- 新增共享 `minimal-system.css`，统一展厅、素材库、剪辑台、账号页和旧整理页面的主要样式。
- 使用近白背景、炭黑与灰色文字、中性无衬线字体、细线分隔、统一按钮和留白。
- 移除印章、渐变、彩色轨道、巨大装饰标题、工具区深色皮肤等视觉干扰；照片本身保留原色。

这是已实现的基础统一，不能据此认为所有旧路由和响应式状态都已经逐页验收完毕。

## 4. 架构与代码地图

| --- | --- |

| `admin/collaboration-store.mjs` | 统一资料库、账号、原始素材、整理与迁移；接入作品存储 |
| `admin/post-store.mjs` | 素材库、草稿、协作、修订冲突、发布快照、作品媒体授权 |

| `admin/materials.js` | 素材浏览、选择及灵感选文 |
| `admin/post-studio.html` / `.js` / `.css` | 剪辑台界面与真实 API 对接 |
| `admin/post-studio-model.mjs` | 片段模型、排序、撤销重做、安全媒体地址与本地备份 |

### 主要路由

| 路由 | 用途与权限 |
| --- | --- |
| `/`、`/posts`、`/guest` | 已发布作品展厅 |
| `/posts/:id` | 已发布作品阅读 |
| `/materials` | 创作者可读范围内的素材 |
| `/studio`、`/studio?id=...` | 新建或恢复获授权作品草稿 |

| `/api/post-media/:id/:index` | 公开快照中的媒体 |
| `/api/post-draft-media/:id/:index` | 获授权草稿媒体 |

## 6. 如何运行与预览

日常真实网站沿用根目录“启动.bat”“关闭网站.bat”，固定域名和通道维护见 `docs/固定域名接入.md`。不要为了界面预览随意重启真实服务或更换资料库。

开发命令：

```powershell
npm install
npm run dev
npm run build
npm run admin
```

`npm run dev` 是前端模板开发，不等于完整统一后台。`npm run admin` 默认使用真实工作目录资料，启动前先确认目标。服务支持 `COLLAB_ROOT`、`COLLAB_PORT`、`COLLAB_PUBLIC_ORIGIN` 配置；具体语义以服务器代码为准。

这些是设计参考，不是已逐项复制的功能。最新极简要求优先于之前偏电影感、装饰性更强的探索。新增界面先使用共享设计规则，避免各页独立定义一套字体、按钮和配色。进一步的架构说明见 `docs/作品与素材架构.md`。

1. 全路由检查视觉一致性，特别是旧管理页、专题整理页、空状态、错误状态和移动端。
2. 用隔离数据补做访客、普通账号、创作者、作品发起人、受邀协作者、站主的端到端验收。

5. 执行最终测试与构建；审阅 Git 差异，确认私有文件未纳入。
6. 备份真实资料后进行正式服务升级与公网验收。当前未完成此步。

### 继续增强作品创作

- 作品话题与专题组织，重点是成品关系而非公开原始事件。
- 版式模板、图文节奏和作品封面；保持入口精简。
- 图片裁切与构图。
- 音视频片段入点、出点、裁取；当前只有嵌入与播放，不是音视频剪辑器。
- 素材导入预处理、重复检测、失败恢复与媒体可用性检查。
- 是否推进实时协作，需要另行设计，不应以当前保存机制冒充。

### 保留但不应抢占核心的能力

人物、时间线、旧事件分类、回收站与旧内容恢复仍有整理价值，应放在创作者工作流程内，避免再次膨胀成多个公共主入口。历史文档中的“所有旧事件 draft 转正”不再是当前发布方案，公开发布以作品快照为准。
